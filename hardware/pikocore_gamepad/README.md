# pikocore_gamepad

A new, independent handheld sampler/mangler — same purpose as the pikocore port in
this repo's root, but built from scratch around the **Waveshare RP2350-Plus** core
module with its own carrier PCB, not the RP2350-PiZero + GamePi13 HAT the rest of
this repo targets.

## Firmware target — `PIKO_GAMEPAD=ON`

```
mkdir -p build-gamepad && cd build-gamepad
cmake -DPICO_SDK_PATH=../pico-sdk -DPIKO_GAMEPAD=ON ..
make -j4
```

`PICO_BOARD` becomes `waveshare_rp2350_plus_16mb` (from the Pico SDK). The flag
reuses the whole GamePi13 port (12-button input layer, LCD UI, USB bank loader)
and swaps only what the carrier PCB changes:

- **Pins:** [`src/boards/pikocore_gamepad/config.h`](../../src/boards/pikocore_gamepad/config.h)
  (`PIN_*`, generated by hand from `pcb/pinmap.py`, kept in sync by gate G-4) mapped
  onto the shared `GAMEPI_*` names in `src/hw_gamepi13.h`. All 12 buttons use
  `gpio_pull_up()`; the NAV5 centre press (`BTN_OK`, GP26) is a second Start.
- **Audio:** I2S to the PCM5102A over PIO0 (`src/gamepad/i2s.pio`,
  `src/gamepad/audio_i2s.h`), BCK GP16 / LRCK GP17 / DIN GP8 at 48 kHz. The
  audio engine still ticks off a PWM slice (slice 0, no GPIO routed) exactly as the
  PWM build does; a DMA channel in endless mode zero-order-holds its latest sample
  into the I2S FIFO. `DAC_XSMT` (GP22) stays low until clocks run and the first
  samples are out, then goes high. `SPK_SHDN` (GP20) follows `JACK_DET` (GP21,
  pull-up): plug in = speaker off.
- **LCD:** same vendored ST7789 driver on SPI0 (SCK GP2, MOSI GP3, DC GP5, RES GP6,
  BLK GP7 PWM), no CS line (`GAMEPI_LCD_CS_PIN -1`, skipped in `dev_shim.c`).
- **Not built:** microSD (no socket; mode 8 stays unreachable, FatFs is not linked)
  and the HDMI mirror. `PIKO_GAMEPI13=ON` keeps building unchanged.

**Not bench-tested.** There is no assembled board yet: the target compiles, gate
G-4 passes, and the I2S/mute/jack sequencing follows the PCM5102A and PAM8302A
datasheets, but nothing above has run on hardware. First things to check on a
real board: DAC lock and unmute click, speaker/jack switching, the LCD SPI clock
(`GAMEPI_LCD_SPI_HZ`, left at the GamePi13's 10 MHz), and button polarity.

## `pcb/`

A scriptable KiCad generation pipeline (Python: `pinmap.py`, `netlist.py`,
`gen_sch.py`, `gen_pcb.py`, `checks/`), forked and adapted from a sibling project
(`GAMESETUP`) that targets the same RP2350-Plus module. Current state: schematic
generates cleanly, ERC passes (0 errors), the pipeline's own automated check suite
passes except for pre-existing GAMESETUP-inherited provisional part/measurement
items (gate G-0 — audio jack part, tact switch part, boost inductor value, LCD
physical measurements). The enclosure and a confirmed BOM purchase order are
still out of scope — see the plan doc's "Out of scope" section for what's next.

`PARTES.md` and `PENDIENTES.md` inside `pcb/` are inherited from GAMESETUP and
describe *that* project, not this one — kept for the component research they
contain (verified footprints, part-sourcing decisions), marked historical at the
top of each file.
