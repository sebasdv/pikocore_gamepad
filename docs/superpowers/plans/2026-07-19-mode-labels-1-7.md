# Etiquetas de Function A/B para los modos 1-7 — Plan de Implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Agregar las 14 etiquetas gráficas de Function A/B de los modos 1-7 (2 por
modo) a la tabla `kModeABitmap`/`kModeBBitmap` ya existente, reemplazando sus 14
`nullptr` restantes.

**Architecture:** Extensión pura de datos en `src/gamepi13/ui_bitmaps.h` — los 14
arrays se extraen mecánicamente (mismo método `sed` ya usado dos veces este mes) desde
`MODE_1.txt`..`MODE_7.txt`, se envuelven en `ModeLabelBitmap` (struct ya existente), y
se referencian desde `kModeABitmap[1..7]`/`kModeBBitmap[1..7]`. `ui.cpp` no se toca —
`draw_function_label()` ya elige bitmap-o-texto según el puntero.

**Tech Stack:** C/C++17, sin dependencias nuevas.

**Spec:** `docs/superpowers/specs/2026-07-19-mode-labels-1-7-design.md` (aprobado).
Rama: `port/rp2350-gamepi13`.

### Hallazgos que hay que respetar

- **Los 14 arrays ya fueron verificados** (ancho×20 exacto contra cada fuente) antes
  de escribir este plan — la extracción `sed` es segura, nunca se retipean a mano.
- **Orden de declaración en C++ importa**: `kModeABitmap`/`kModeBBitmap` (definidos en
  `ui_bitmaps.h`, después de `kBreakFxWordBitmap`) van a referenciar los 14
  `ModeLabelBitmap` nuevos — esos structs (y a su vez los 14 arrays de píxeles) deben
  quedar declarados ANTES de `kModeABitmap`/`kModeBBitmap` en el archivo, no después.
  Por eso los dos `sed` de este plan insertan contenido en medio del archivo (después
  de `kBreakFxWord` y después de `kBreakFxWordBitmap` respectivamente), no al final.
- **Mapeo modo → archivo → assets → anchos** (ya verificado, ver spec para el detalle):
  Modo 1: `MODE_1.txt` → FILTER(92)/STRETCH(105). Modo 2: `MODE_2.txt` →
  GATE_1(62)/P_GATE(93). Modo 3: `MODE_3.txt` → JUMP(62)/P_RETRIG(120). Modo 4:
  `MODE_4.txt` → TUNNEL(90)/P_REVERSE(134). Modo 5: `MODE_5.txt` →
  REC_SEQ(105)/PLAY_SEQ(120). Modo 6: `MODE_6.txt` → SAVE(61)/LOAD(63). Modo 7:
  `MODE_7.txt` → VOLUME(92)/TEMPO(77). Todos con alto 20.
